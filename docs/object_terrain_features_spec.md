# Object-derived terrain features — tunnels, below-grade structures, and taxiway bridges

**Reads with:** [`docs/dsf_object_integration_spec.md`](dsf_object_integration_spec.md) (the OBJ8
reader/footprint/y-bake machinery this feature extends) and
[`docs/dsf_object_anchor_plan.md`](dsf_object_anchor_plan.md) (the anchor physics — §4 and §7.3 are
prerequisites for every agent touching geometry here). This document is the *design and build order*
for two new object classes: **tunnels / below-grade structures** (feature A) and **taxiway bridges**
(feature B).

**Evidence base:** the 2026-07-09 three-pack investigation (EGLL TaiModels, Nimbus KBNA + Nashville
Roads, Aviotek EDDF) and the dissection of the author-supplied EGLL base mesh (§2.4). Probe scripts
from that session: `tunnel_probe.py`, `rim_probe.py`, `mouth_probe.py`, `bridge_probe.py`,
`aptdat_bridge_scan.py`, `pavement_coverage.py` (session scratchpad; promoted probes land in
`tools/` per W-V).

**Baseline:** `dev` (post 9345739, runway-end skirt anchored at the runway end). Working-tree state
of `adjacent_ground.py` (node-split welded walls) is a dependency of feature A emission.

**Shape of the work:** one shared classifier library feeding two independently gated terrain
features.

| | Feature A — tunnel cutouts | Feature B — bridge adaptation |
|---|---|---|
| what | flatten band over roofed body + open trench at the mouths | terrain meets the deck ends; depressed road corridor under the span |
| exemplar | EGLL (20 tunnel objects) | KBNA taxiway L (deck-carried), EDDF taxiway P (terrain-carried) |
| solver involvement | flat anchor seat at the datum; pins/ceilings where a rim abuts pavement | deck-end hard pins (seam-pin idiom); everything else lawful grading |
| emission | late block, skirt-style, welded node-split walls | existing underpass-corridor emitters, re-sourced from object geometry |
| flag | `O4_OBJECT_TUNNEL_TERRAIN` (default off) | `O4_OBJECT_BRIDGE_TERRAIN` (default off) |

## 0. Rulings in force

Decided; do not relitigate. If implementation proves one wrong, stop and escalate.

**R1 — One-solve doctrine (user, 2026-07-09, chain-identity session).** All laws live in
`grade_law.py`; minimize post-solve mutation; solver performance is first-class. Feature B's
deck-end coupling therefore lives *inside* the solve as pins, not as a post-solve rewrite. Feature
A's trench is off-pavement terrain (outside the solver's domain) and is emitted, but its *law* — rim
and floor elevations as a function of datum and deck profile — is a `grade_law` function imported by
both the emitter and the validator (lockstep, same as the runway-end skirt).

**R2 — Weld ruling (user, 2026-07-09).** Emitted strips weld fully to pavement; deliberate
divergence only via node-split walls (two coincident node rows carrying different values). Trench
rims weld to surrounding terrain values; the vertical drop is a node-split wall. Pavement value
always wins at any contact.

**R3 — No true mesh holes.** The mesh is a 2.5-dimensional heightfield; Triangle's hole plumbing is
unused and untested end-to-end. Feature A models *open-cut trenches*, never voids. §2.4 records what
the author's own mesh does; even if X-Plane tolerates base-mesh holes, we do not emit them in this
iteration (revisit only with a user ruling).

**R4 — Phase-2 interlock (designer, this spec; consequence of R1/R2).** An object whose terrain is
carved or seated to match it (any structure consumed by feature A or B) is **excluded from the
Phase 2 y-bake**. Terrain-to-object and object-to-terrain corrections must never stack. The
classifier emits the exclusion list; `post_mesh.rebake_dsf_objects` consumes it.

**R5 — Contract before shape (designer, this spec).** No bridge terrain is emitted until the
structure's contract is classified (deck-carried versus terrain-carried, §3.2). Ambiguous
classifications (pavement coverage between the thresholds, or no `ATTR_hard_deck` found) are
refused and reported, never guessed.

**R6 — Pack fixtures are synthesized, never copied.** Third-party pack content (OBJ8, DSF, apt.dat)
must not enter the repository. Test fixtures are minimal synthetic files generated by the tests
themselves, shaped like the real signatures (roof-at-zero shell + sunken deck; hard-deck plane +
abutments).

**R7 — No abbreviations in identifiers** (user, standing, all projects). `heading_degrees`, not
`hdg`; config-constant unit suffixes `_M` / `_M2` remain the established exception.

**R8 — Hard-deck flush seating (user, 2026-07-09).** When the pack provides a hard deck object
(`ATTR_hard_deck`), **our pavement is cut over that object's footprint** so the object sits flush
and carries the drivable surface: tunnel roofs (pavement cut over the trench body — the roof is
the ground there) and deck-carried bridge spans (pavement cut between the abutment lines, the
pattern the KBNA author already uses). This resolves open question 5: no pavement is left
coplanar over a hard roof slab. A **non-hard** roof or deck gets no cut — pavement wins (R2) and
the object stays cosmetic beneath it.

**R9 — The vertical split is derived, never assumed (user requirement, 2026-07-09).** Bridges
divide the taxiway-to-road separation between road depression and taxiway rise differently per
airport (KBNA: road fully depressed, deck level with the taxi network; EDDF: terrain ramps up to
an elevated span over a partially lowered highway; KMCO/KDFW: flat surrounding base, the bridge
itself rises over a road lowered little or not at all). The model must express the whole family:
the split is read from the object's deck profile and the road's actual elevation state (§3.2),
never hard-coded per style.

**R10 — Interior cutouts under split-depth buildings (user, 2026-07-09).** A building that is
mostly at grade but has portions extending below gets an **interior mesh cutout**: the mesh is
carved inside the structure's at-grade footprint (perimeter stays at grade where facade bases
are at grade) down below the below-grade content, so modeled underground spaces are visible
from INSIDE the building. Exemplar: KDEN's underground train stations beneath each terminal.
This refines A6's buried-by-default: burying remains correct for un-enclosed below-grade slack
(the EGLL jetway class) and where pavement covers the piece, but enclosed below-grade interiors
are cut by default — harmless from outside (hidden by the building), necessary at KDEN. Guards
(calibrated by the KDEN measurement pass, amendment pending): cut strictly inside the at-grade
footprint; never carve pavement; enclosure of the below-grade piece within the parent
structure's at-grade footprint is the trigger. Corrected exemplar note (user): **LFPG Terminal 1
is genuinely set below apron grade** — a sub-grade level with the road deck nearer apron level
above it, so the whole terminal area is cut below apron grade (A5's "foundation moat parasite"
reading was wrong); the multi-level-central-spine pattern is **Terminal 2**. The user's
hand-built patch (`Ortho4XP-1.40.12/Patches/+40+000/+49+002/LFPG.patch.osm`) is the reference
treatment; a measurement pass against it is in flight.

**R11 — Correlating custom mesh as cutout oracle (user, 2026-07-09).** When a custom base mesh
exists and correlates with the custom airport pack (the EGLL_MESH case), consulting it to find
and confirm cutouts is useful and **allowed**: buried-versus-exposed disambiguation, cutout
footprints and depths, and datum reference. This promotes the A6 correlation methodology from a
one-off audit to a sanctioned input — an oracle module samples the author mesh where present
and (a) confirms/overrides classifier calls (the EGLL `4.obj` bridge-versus-buried case, the
KDEN Jeppesen escalator case), (b) supplies cutout footprints the objects under-specify. Object
evidence remains the primary path; the oracle refines where it exists. Open question 1's datum
half (copy the author elevation versus solve our own) remains open — the oracle *reports*
datum deltas, it does not yet impose them.

**Agents additionally must not:** run `git add`/`git commit` (the supervisor reviews and commits);
edit files owned by another workstream (§5 ownership map); write outside the repository and the
session scratchpad.

## 1. Scope and non-goals

**In scope**

* A structure classifier (`src/auto_patch/object_terrain_features.py`) recognizing tunnel and
  bridge structures from OBJ8 geometry plus placements, and classifying each bridge's terrain
  contract.
* Placement-reader extensions: `OBJECT_MSL` rows (currently skipped — at KBNA they are the only
  absolute elevation source) and negative `OBJECT_AGL` offsets as a below-grade signal.
* A DSF road-network reader (`BEGIN_SEGMENT` / `SHAPE_POINT` with the draped-versus-elevated level
  flag) as a road source alongside OpenStreetMap — the KBNA bridged roads exist only there.
* Feature A: flatten seat + mouth trenches for below-grade structures (EGLL class).
* Feature B: deck-end pins + object-sourced underpass corridors (KBNA class); at-grade continuity
  for terrain-carried decks (EDDF class).
* Replacement of the boolean `_scenery_has_bridge_objects` name-grep (misses every EDDF crossing)
  with classifier output.
* Feature C (measurement-gated, A3): split-level structure interfaces — per-facade ground-contact
  levels extracted from terminal/station objects as elevation evidence for
  airside/groundside/roadway/rail grade separation (ELLX / LFPG / LFLL class).
* Verification audits promoted into `tools/`.

**Explicitly out of scope**

* True mesh holes (R3).
* The EDDF cosmetic swale (depressing terrain about 1 m inside trench-cladding interiors). The
  terrain-carried contract needs *flat grade across the deck*, which the solver already produces;
  the swale is cosmetic-only and lands later behind its own flag if the user wants it.
* Roofed-bore rendering, road traffic, or any DSF rewriting.
* Draped-cosmetics rescue (facade guardrails, painted lines, forests sinking into depressed
  corridors). Known, logged by the emitters, fixed in a follow-up.
* Re-anchoring the deep below-grade *building* geometry found at EGLL (`T2_T3_3.obj` at −9.2 m and
  kin) — that is Phase 2 worklist material, not a terrain feature.

## 2. Evidence and the physical model

### 2.1 EGLL tunnels (feature A exemplar)

Twenty `Airport/Tunnel/*.obj`, one placement each, **all heading 0**. Pairing convention: `N.obj` =
shell (roof top flush at local y = 0, walls to −4…−7 m); `Na.obj` = road deck (flat at −4…−5 m,
ramps rising to 0 at the mouths). Cut-and-cover: only the mouths are open to the sky. Seventeen
plain `OBJECT`; three `OBJECT_AGL` with negative offsets (−1.0, −7.0, −7.5 m) — above-grade
geometry placed below grade, invisible to a vertex-depth filter alone.

**Mouth derivation (validated):** plane-sectioning the shells fails (open shells, duplicated seams
— curve soup, 0–2 closed of 34–54). **Union of projected up-facing triangle footprints** succeeds
by construction: mouths = deck footprint − roof footprint, yielding clean 4–21-vertex polygons
(tunnel 2: four mouths, 890–5,052 m²). Depth inside each mouth comes from the deck triangles it
contains.

**Signatures (A6 — mesh-validated, replacing the depth heuristic):** a structure is a tunnel
(cut a trench) **iff** it has a *drivable* surface (`ATTR_hard` / `ATTR_hard_deck`) whose
triangles reach below effective grade, OR a negative `OBJECT_AGL` offset ≤ −1 m. Depth alone is
**exactly inverted** as a signal: the deepest below-grade geometry in the pack is buried
building basements (`T2_T3_3` at −9.22 m), while exposed tunnels run only −4 to −5 m. Validated
against the author mesh: zero wrong on all 30 below-grade building objects and all 20 tunnels.
`Tunnel/` naming remains a secondary hint only.

### 2.2 KBNA bridges (feature B, deck-carried contract)

Pavement (all DSF draped polygons; the apt.dat has zero code-110 rows) is **cut at the abutments**
— mid-deck pavement coverage 0%. The `ATTR_hard_deck` deck at +5.99 m above anchor terrain carries
the taxiway; the road drapes level-0 beneath (polylines in the sibling Nashville Roads pack's DSF
road network). Taxiway L: 131 × 55 m deck, heading 108°, girder underside +4.2 m. Twelve
`OBJECT_MSL` centerline fixtures at 166.9994 m pin the deck top absolutely → deck 167.0 m, corridor
161.0 m above sea level. The Murfreesboro service bridges have **no** hard deck (cosmetic): trucks
ride the terrain, so the causeway-plus-corridor shape is mandatory there.

### 2.3 EDDF bridges (feature B, terrain-carried contract)

Hard decks flush at y = −0.02; apt.dat pavement drapes **continuously across the spans** (30–78%
of the deck box); paired `Tunnel_N` cladding has its visible floor at only −1.0 m (headroom is
texture) with wall skirts to −6.02 m. Terrain must stay at taxiway grade across the deck. The
`sim/exclude_net` zones sit exactly under two of the crossings; under the others the live road is
in the default base mesh, outside the pack.

**Contract disambiguation (validated on both packs, refined by A4):** pavement-coverage fraction
of the mid-deck box — ~0% ⇒ deck-carried; above ~30% ⇒ pavement-continuous — cross-checked by
road-network level flags beneath. Pavement-continuous then splits on the measured deck profile:
flat ⇒ **terrain-carried** (EDDF flush decks); non-flat (sloped/crowned) ⇒ **profile-carried**
(KMCO humps, the EDDF A3 ramp) — the deck profile is the pavement's elevation target, so "flat
across" handling would erase the hump. Thresholds are config constants; the band between the
coverage thresholds is refused per R5. Two more mechanical guards from the A4 measurement pass:
drivable surfaces may be `ATTR_hard` rather than `ATTR_hard_deck` (KMCO and the EDDF ramp carry
zero `hard_deck` triangles — keying on `hard_deck` alone misses every humped bridge measured),
and **piered viaducts are excluded by the abutment-reaches-grade test** (solid geometry must
reach local y ≈ 0 at each profile end; KMCO's rail viaduct never comes below +3.45 and would
otherwise induce a false causeway).

### 2.4 The author's own EGLL mesh — datum and cutout ground truth (amendment A1)

Dissection of `c_GBR - 100_airport - EGLL_MESH/Earth nav data/+50-010/+51-001.dsf` (MeshTool-made
per `sim/creation_agent`, per-vertex integer-metre elevations, triangle strips + lists, stock
terrain definitions). Four findings bind this design:

1. **No holes exist.** Every tunnel footprint has 100% triangle coverage (grid-sampled,
   thousands of points per tunnel). The cutouts are **depressed open trenches with near-vertical
   walls** — a grade vertex and a deck vertex at nearly the same longitude/latitude (measured
   drops of 21 m → 15 m within ≤ 1 m horizontal). This is exactly our node-split wall mechanism
   (R2); the file does **not** demonstrate sim tolerance of base-mesh holes, so R3 stands on both
   grounds.
2. **The author cuts the ENTIRE tunnel body, not the mouths.** Tunnel 2's trench floor runs
   continuously at 15 m for the full ~1,030 m body (bbox longitude −0.487057..−0.471960); our
   four derived mouth polygons are subsets of that one cut. The at-grade surface over the body is
   supplied by the overlay pack's roof *object* (top at local y = 0), not by terrain. Rationale
   this design adopts: terrain left at grade under a roof slab whose top is also at grade would be
   coplanar with it and z-fight; cutting the body away makes the roof object the visible ground.
3. **The trench floor sits below the object's road deck, never at it.** Author floors: tunnel 2
   at 15 m where the object deck renders at 16 m (datum 21 − 5); tunnel 9 at 16 m versus deck
   16.5; tunnel 11 at 14 m versus deck 14–15. The mesh never carries the visible road — the
   OBJ8 deck does — the mesh only stays safely beneath it. Floors are flat pans (no longitudinal
   road grade; the object's ramps do the vertical work), quantised to whole metres.
4. **Datum.** A hand-flattened platform at exactly **21 m** covers 97.6% of the airport's
   non-water ground (about 2 m below the author's own source raster; Heathrow's published
   elevation is 25 m); both runways are dead flat at 21.0 m end to end. Tunnel anchors: tunnels
   2, 9, 10, 11 → **21 m**; tunnels 6/7 (northwest rising ground) → **28 m**. These are the
   reference values `tunnel_trench_audit.py` reports deltas against (open question 1: we do not
   copy the author's datum, we solve our own — the audit quantifies the disagreement).
5. **Below-grade building geometry is 100% buried (A6 correlation).** Every below-grade piece
   of every non-tunnel object — all 30 resources, including basements to −9.22 m and 194 jetway
   wheel-slack placements — sits under mesh that runs flat at the platform datum. The author
   exposes *only* drivable tunnel decks. The single non-tunnel interior depression is a 2 m
   T5 landside forecourt sub-platform that still buries everything beneath it by 1.5–3.2 m.
   Corollary confirmed: tunnels are **mesh-walled** (the heightfield makes the vertical drop;
   the object supplies the deck), buildings are the opposite (mesh runs flat underneath, the
   object carries its own invisible below-grade walls). The author's floor sits ~1.0 m below
   the OBJ8 road deck (integer-quantised mesh); our `TUNNEL_FLOOR_BELOW_OBJECT_DECK_M = 0.5`
   satisfies the same strictly-below contract at finer precision.

### 2.5 Why the solver cannot own the terrain shapes

The elevation solver's domain is pavement-network nodes only; off-pavement terrain is written by
post-solve emitters as per-vertex altitudes and baked by Triangle4XP into a continuous heightfield.
"Put the geometry in place and let the solver handle it" therefore covers exactly the parts of
these features that *are* pavement-coupled — deck-end pins, rim-adjacent pavement ceilings, the
flat anchor seat — and nothing else. This is the same split the underpass corridors, retaining
walls, and runway-end skirts already live with.

## 3. Design

### 3.1 Shared classifier — `object_terrain_features.py`

Consumes the placement list (extended per W-R1) and per-object OBJ8 geometry (existing
`obj8_reader` loaders). Produces:

```
TunnelStructure:
    object_resources          # shell + deck file(s), grouped by shared anchor/adjacency
    anchor_longitude_latitude, heading_degrees, placement_kind, above_ground_offset_m
    roof_footprint            # union of up-facing triangles with top near y = 0 (world frame)
    deck_footprint            # union of up-facing triangles below the roof
    mouth_polygons            # deck_footprint − roof_footprint, split to parts
    mouth_depth_samples       # per mouth: deck-triangle y statistics (ramp profile)
    body_depth_m              # deck level of the roofed body

BridgeStructure:
    object_resources, anchor_longitude_latitude, heading_degrees
    deck_polygon                         # plan footprint of the ATTR_hard_deck surface
    deck_top_profile                     # deck top y sampled along the bridge axis (~10 m bins):
                                         #   flat (KBNA), single value; sloped or crowned
                                         #   (KMCO/KDFW class), the full profile — R9
    deck_top_y_m                         # convenience: profile maximum (crest)
    deck_end_elevations_y_m              # profile value at each end — the solver pin values
    ceiling_y_m                          # largest down-facing plane below the deck (clearance)
    abutment_lines                       # deck-end segments where solid geometry reaches y ≈ 0
    abutment_reaches_grade               # per end: solid geometry reaches y ≈ 0 there (A4);
                                         #   an end that never reaches grade ⇒ piered viaduct,
                                         #   refused (no terrain feature)
    contract                             # DECK_CARRIED | TERRAIN_CARRIED | PROFILE_CARRIED
                                         #   | AMBIGUOUS (A4)
    absolute_deck_elevation_m            # from OBJECT_MSL fixtures on the deck, else None
                                         #   (KBNA is the only pack measured that has them)
    hard_deck                            # bool; False ⇒ cosmetic (Murfreesboro class).
                                         #   Detection accepts ATTR_hard_deck OR near-horizontal
                                         #   ATTR_hard planes (A4)

StructureGroundInterface (feature C, A3):
    structure reference (shared with the building-pad pipeline)
    perimeter_base_profile               # minimum solid y binned along the footprint boundary
    interface_levels                     # clustered: [(level_y_m, boundary_arcs, perimeter_share)]
    split_level                          # bool; False ⇒ the existing single flat pad (R5) stands

exclusions: [(pack_root, object_resource)]   # R4 feed for the Phase 2 y-bake
```

Detection thresholds (config constants, no magic numbers in code):
`TUNNEL_MIN_BODY_DEPTH_M = 2.0`, `TUNNEL_ROOF_TOP_TOLERANCE_M = 0.5`,
`BRIDGE_MIN_DECK_AREA_M2 = 200`, `BRIDGE_DECK_CARRIED_MIN_HEIGHT_M = 2.0`,
`BRIDGE_CONTRACT_PAVEMENT_COVERAGE_DECK_CARRIED_MAX = 0.05`,
`BRIDGE_CONTRACT_PAVEMENT_COVERAGE_TERRAIN_CARRIED_MIN = 0.30`.

The classifier is pure (geometry in, records out) and independently testable against synthetic
fixtures (R6). It runs at layout time — Phase 1 already proves OBJ8 data is available there.

### 3.2 Feature B — bridges

**Deck-carried (KBNA class).**
1. *Deck elevation*: `absolute_deck_elevation_m` when `OBJECT_MSL` fixtures supply it; otherwise
   datum-at-anchor (the anchor seat, as in feature A) plus `deck_top_y_m`.
2. *Deck ends in the solve*: abutment lines become pinned polylines using the tile-seam idiom
   (`split_pavement_at_seams` / `apply_seam_dem_anchors`): ring vertices are inserted exactly where
   pavement rings cross an abutment line and hard-pinned at deck elevation. The network grades up
   to them under existing edge budgets — no new solver machinery. Where no pavement ring crosses
   (pavement cut short of the abutment), the causeway approach is emitted analytically from the pin
   value using the existing approach-ramp emitters.
3. *Corridor*: `_emit_underpass_road_approaches` re-sourced — span footprint, clearance, and floor
   elevation from the `BridgeStructure`; road centerline from the DSF road network (W-R2) with
   OpenStreetMap fallback. Corridor floor = deck elevation − structure depth − clearance margin
   (KBNA: 161.0 m, confirmed by both the fixture pins and the anchor sample).
4. *Gate replacement*: `_scenery_has_bridge_objects` boolean grep retired in favor of classifier
   records (it currently misses all four EDDF crossings and suppresses our own deck emission
   wherever it does hit).

**Terrain-carried (EDDF class), generalized by R9.** The pavement drapes across the span and is
already in the solve. Two sub-cases by road state:

* *Road fully handled by the pack* (cosmetic trench, EDDF flush decks): the deliverable is
  restraint — the corridor/trench emitters must not fire under the deck (today an OpenStreetMap
  `bridge=yes` way beneath could trigger a carve that breaks the causeway). Classifier records
  suppress corridor emission inside terrain-carried deck footprints and log the suppression.
* *Road not (or only partially) lowered* (the EDDF elevated span; the terrain must RISE): a new
  law, `grade_law.bridge_crossing_floor`, puts a **floor band on the pavement nodes inside the
  span footprint**: floor = road surface elevation + `BRIDGE_ROAD_CLEARANCE_M` +
  `BRIDGE_DECK_STRUCTURE_THICKNESS_M` (structure depth from the object: deck top − ceiling).
  Per-node floors are first-class solver inputs (`node_band`), so **the hump solves itself**:
  the one-solve raises the crossing to the floor and the existing taxiway grade cap (1.5%) and
  vertical-curvature law shape the approach ramps on both sides — no ramp geometry is authored.
  Road surface elevation source, in order: the pack's own trench/cladding floor (partial
  depression, measured from the object) → the DSF road network's draped polyline over our solved
  corridor → the digital elevation model where the road is untouched. Where the object's own deck
  profile is sloped or crowned (KMCO/KDFW class), the deck-end profile values additionally pin
  the pavement at the span ends so the rendered object and the solved pavement meet exactly; the
  object's crest must sit at or above the solved crossing (audited, W-V).

**Profile-carried (A4; KMCO humps, EDDF A3 ramp).** Pavement is continuous across the span AND
the measured deck profile is non-flat: the object is the authority for the vertical shape and
the terrain is graded up to follow it. Handling: per-vertex profile pins along the span —
pavement nodes inside the deck footprint pinned to datum + profile(axis position), the exact
mechanism runway profiles already use (per-vertex `alt_abs` from birth). The crossing-floor law
still applies as a lower bound; approach grades outside the span solve normally (measured
approaches: 3.7–4.9% at KMCO, 9.4% on the EDDF hard ramp object — the ramp is drivable object
surface, so the solved terrain beneath tracks it from below, never above). Abutment ends that
reach grade are the anchor points; a structure failing the abutment-reaches-grade test at either
end is refused (piered viaduct, no terrain adaptation).

**Pack-data gap (A4; KDFW).** Aerosoft KDFW models neither deck geometry nor road depression —
the parkway is a DSF road network draped at grade and no bridge object exists. Nothing to
extract ⇒ feature B does not fire; the existing OpenStreetMap `bridge=yes` underpass machinery
(built on KDFW) remains the handler. This is the designed fallback, not a failure mode.

**Cosmetic decks** (`hard_deck = False`): treated as deck-carried for terrain purposes (the truck
routes ride the terrain, which must form the causeway and corridor), but the deck-end pin values
come from datum + deck geometry only — there are no fixtures.

### 3.3 Feature A — tunnels

1. *Datum / anchor seat*: the roofed body (roof footprint) enters layout as a **flat seat** at the
   anchor's solved elevation — the same mechanism as building pads (flat, heavy anchor), new role
   distinct from `ROLE_BUILDING` so validators can tell them apart. This fixes `terrain(anchor)` at
   layout time and breaks the circular datum (§2.4 supplies the reference values the result is
   audited against).
2. *Trench footprint* (amended by A1): the trench is the **full deck footprint** — body and
   mouths — not the mouths alone. The roof object is the at-grade surface over the body; terrain
   left at grade there would be coplanar with the roof slab and z-fight (§2.4). The trench
   polygon is carved out of any overlapping pads/boundary shapes at layout time (precedent:
   `_depressed_road_corridor_band` carving terminal pads), so nothing solves *over* the opening.
   Where the trench rim abuts solved pavement, those pavement nodes get a band ceiling at rim
   elevation. **Pavement overlap**: where auto_patch pavement itself crosses the body footprint,
   pavement value wins (R2) and the trench is carved only outside it — the resulting
   roof-slab-versus-pavement coplanarity is open question 5.
3. *Law*: `grade_law.tunnel_trench(datum, trench_polygon, deck_depth_samples) → rim ring +
   floor elevations`. Floor = deck depth **minus `TUNNEL_FLOOR_BELOW_OBJECT_DECK_M` (0.5)** —
   the mesh floor must sit strictly below the object's road deck, never at it (§2.4 point 3; the
   OBJ8 deck carries the visible road, the mesh only clears it). A flat pan per tunnel at the
   body's deck depth is lawful (validated in the wild); following the mouth ramp bins upward is
   permitted but optional. Rim = datum. Emitter and validator import this one function (R1).
4. *Emission*: last-block, skirt-style (after final grade projection and decimation, own
   `tile_cut`), emitting the floor polygon and node-split wall rows per R2. Rim welds to
   surrounding terrain; walls are the deliberate divergence.
5. *Interlock*: every consumed tunnel object lands on the R4 exclusion list; Phase 2 must not
   y-bake it. Negative-`OBJECT_AGL` tunnels (EGLL 6/7/10) are consumed with their offset applied to
   every depth (their geometry is authored above y = 0).

### 3.4 Feature C — split-level structure interfaces (measurement-gated)

**The evidence class (user, 2026-07-09):** airside and groundside commonly sit at different
grades with buildings between them, and the *object's construction* encodes the split — facade
bases at different local y on different sides. Three exemplar patterns: ELLX (terminal between
airside and a lower groundside: the landside base level says exactly where groundside sits);
LFPG (terminals abutting a central roadway lower than the aprons, the objects extending down
along it); LFLL (a railway station built around below-grade rail). The principle is the same as
features A/B: read the object for what the terrain must do, both to adapt the object to the
terrain and the terrain to the object.

**Extraction (as measured, A5):** the classifier records, per compass/radial sector of the
footprint boundary, the **low envelope** of facade bases — the minimum (≈ 5th percentile) solid
y of *wall columns* (vertical extent ≥ 2.5 m; roof-overhang and draped-decal edges otherwise
dominate as false levels), clustered at 0.5 m with a **minimum perimeter share (~5%)** per level
to drop basement/service parasites. A single level ⇒ the existing flat building pad (R5
unchanged). Multiple levels ⇒ piecewise-flat: one seat per interface level — R5 refined per this
user direction, not overturned.

**The A5 measurement verdict reframes the consumers.** The loud facade bands are DECOYS: at
ELLX the 5–10 m landside band is an *elevated departures roadway* (ramp objects rising 0 → 7.6
and 0 → 9.1 m from grade) and at LFPG the central access is an *elevated ring-road viaduct*
(wall base +4.27 m) — in both, ground-level geometry (y ≈ 0) co-exists on every side and the
correct terrain answer is **flat at grade**. The low envelope gets all three airports right; a
classifier trusting the dominant or highest interface would seat groundside several metres
wrong at two of them. Consumers, ordered by evidence:
1. *Groundside seating and the bowl-under-deck rule (ELLX versus LFPG T1, refined by A7).* The
   seat is the **low envelope** per side, and the deciding signal is the **ground-contact
   fraction**: when substantial y ≈ 0 geometry co-exists on a side (ELLX: both sides), terrain
   is flat and the vertical drama is object-carried — restraint with confidence. When a
   structure has essentially **no** ground-contact geometry (LFPG T1 drum: 0–23% per object),
   the **low envelope wins as a real bowl**, and a co-occurring elevated road deck *above* the
   same footprint (T1's 0 → +17.6 m helix) confirms bowl-under-deck rather than refuting it —
   the exact inverse of the ELLX decoy, separable only by the ground-contact test. Measured
   caveat: objects under-specify bowl *depth* (T1 shell base −3.4 m where the user's hand patch
   cuts −8 m) — the object gives existence, footprint, and a floor bound; depth margin, rim
   extent, and approach ramps are law/audit territory (the hand patch is the reference).
1b. *Interior cutouts (KDEN class, R10 — guards calibrated by A8).* Trigger: the structure
   contains drivable (`ATTR_hard_deck`/hard) triangles below effective grade that are ≥ 95%
   **enclosed** within its own at-grade plan footprint. Cut footprint = the enclosed below-grade
   hall (inset from the perimeter; perimeter ring stays at grade, node-split welded per R2).
   Floor = the below-grade **hard content's** minimum y minus a small clearance — keyed on the
   platform, never the deepest solid (KDEN carries non-hard foundation piles to −19 m; keying
   on deepest solid would blow the pocket floor 9 m past the platform — the interior-cutout
   analogue of A6's depth inversion). Guard (b) is perimeter-scoped: **never lower pavement
   nodes outside the structure footprint** — NOT "refuse when apt.dat covers the footprint"
   (KDEN's A/C platforms sit directly under apron concrete; the cut lives inside the building
   perimeter and the taxied pavement outside stays at grade). Enclosure is what separates this
   rule from the A6 tunnel rule (EGLL decks are open to the sky at the mouths; KDEN platforms
   are 100% enclosed), and the negative-`OBJECT_AGL` limb must NOT drive cutouts (at KDEN it
   catches only jetway slack and sunk signage — pure false positives here).
2. *Below-grade trench interfaces (LFLL class) — the surviving v1 scope.* The Lyon TGV station
   is cleanly bimodal: concourse at 0, rail trench floor at −10 m (min −10.9, box ≈ 121 × 773 m
   along the rail axis), with a −2 m mezzanine band to keep distinct. The −10 m depth exists
   ONLY in the object (the Roads-pack DSF network carries the alignment but is draped level-0,
   no metric depth). Treatment = feature A's trench machinery: floor from the object's trench
   interface, alignment from the DSF network / OpenStreetMap rail, walls largely provided by
   the station object (R8 spirit).

**Gate:** `O4_OBJECT_SPLIT_LEVEL_TERRAIN` (default off). v1 implements only the LFLL-class
below-grade trench interface plus the flat-confirmation low envelope; depressed-frontage seating
(the original ELLX/LFPG hypothesis) stays parked until an airport measures a real depressed
interface. Split-level structures whose terrain is adapted to them join the R4 exclusion list
exactly like tunnels. Anchor caution carries over from families A/B: these packs bake geometry
150 m–3.3 km from a single shared anchor, so the datum is one sampled terrain point.

### 3.5 Pipeline ordering (unchanged laws, new participants)

```
layout: placements + OBJ8 → classifier → seats, mouth carves, exclusion list
solve:  seats as flat anchors; abutment pins via seam idiom; rim ceilings
post-solve emitters (existing block): corridor + approaches (feature B)
…planarize → decimate (ordering law) → final grade projection…
last block (with runway-end skirts): mouth trenches + walls (feature A)
to_osm → Triangle4XP mesh → Phase 2 y-bake (minus exclusion list)
```

The known failure this respects: emitters that bake pavement reads before
projection/decimation get rewritten underneath (the reason skirts emit last). Feature B's coupling
is inside the solve (pins) so its corridor emission may stay in the existing block; feature A's
trench reads final values and therefore emits last.
