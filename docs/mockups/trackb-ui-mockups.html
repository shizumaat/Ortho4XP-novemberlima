Main window · searching “bre”, three tiles selected (solid = active +48-006 with info pane, dashed = ⇧/⌘-click additions). The Zones tool switches the same window into View 04.

M1
Search is feasible offline. Airports: parsed from X-Plane's Global Airports apt.dat (ICAO, name, city, country → lat/lon) into a local index at onboarding. Cities/countries beyond that come from a small bundled gazetteer (~5 MB, GeoNames extract). Selecting a result zooms the map and selects the containing tile.
M2
The live zoomable map is a yes. Ortho4XP already knows how to fetch any provider's tiles (O4_Imagery_Utils URL templates + request code). A QGraphicsView tile layer requests the visible tiles at the current zoom from the selected source, async, into the existing disk cache — no web engine needed, works offline from cache. Low zooms use the provider's own low-ZL tiles, so coverage gaps show up honestly before you build.
M3
Selection gestures exactly as specified: click = select, ⇧click = contiguous rectangle, ⌘/Ctrl-click = toggle non-contiguous; pinch and scroll zoom, two-finger/secondary drag pans. The hint chip fades after first use. Q: should plain left-drag rubber-band-select, or stay reserved (pan on drag) to avoid accidental selections?
M4
Info pane for a built tile, exactly your field list: imagery source, ZL (+zone count), mesh date, imagery date, size on disk — all read from the tile folder (cfg + file mtimes; dir size scanned once and cached). Plus the install toggle, replacing Ctrl-click symlinking.
M5
Build zooms to the selection and locks the map (View 03). Steps are collapsed to three meaningful checkboxes; “Rebuild existing” guards against accidental re-downloads of built tiles in the selection. Q: is collapsing steps 1–3 into “Vector · mesh · masks” acceptable, or do you still want the four-step split visible here?
M6
Changing Imagery or ZL re-renders the map live from the new source, so provider comparison is a two-click A/B. Build ZL is annotated on the grid at high zooms (texture-block boundaries).
M7
Everything else lives in Actions (and the menu bar): zones, GeoTIFF export, mesh extraction (both were buried in the old zone editor), community mesh, cache cleanup, open folder. Overlay linking and batch cache cleanup live under Tools. Q: anything you'd promote from this menu to a top-level button?
View 03 — Building

Progress lives in the tiles

Clicking Build zooms to the selection and locks map editing. Each tile carries its own progress: indeterminate while queued for its first step, determinate once its build starts. The right panel becomes the activity list; the console is a drawer below the map.

B1
Map locks on build — selection and zone editing disabled; pan/zoom stays enabled for watching (view-only). Title bar mirrors overall % for the Dock/taskbar. Q: you said “disabled” — should even pan/zoom lock, or is view-only right?
B2
Indeterminate → determinate per tile, as specified. Mesh triangulation stays indeterminate (Triangle4XP gives no % — shown as a spinner + live triangle count); download/convert/DSF phases are determinate. Honesty note on concurrency: today the pipeline builds tiles sequentially with parallelism inside a tile. True parallel tile builds are a backend change (RAM + Triangle4XP contention); the realistic v1 is pipeline overlap — tile N downloads imagery while tile N+1 triangulates — which is what's mocked (3 active). Q: is overlap acceptable for v1, with full parallel builds as a later option?
B3
Activity panel replaces the right panel during builds: overall bar + ETA, one card per active tile with step, %, thread counts, throughput. It's a panel, not a floating window, so nothing gets lost behind the map — but it can pop out via drag if you want it on another monitor. Q: panel or separate window as the default?
B4
Console is a collapsible drawer under the map (toggle in the status bar), with level/filter/copy/save; lines are prefixed with their tile so interleaved multi-tile output stays readable.
